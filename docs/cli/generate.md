# loom generate

Generate code from blueprints.

## Usage

```bash
loom generate schema                              # Generate models
loom generate migration -m "Description"            # Create database migration
```

## Subcommands

### `loom generate schema`

Generates `models.py` from all blueprints.

**Usage:**
```bash
loom generate schema
```

**Output:**
```
⏳ Generating models from blueprints...
✅ Generated models.py with 5 entities
  - Company
  - Contact
  - Deal
  - Activity
  - User
```

**What it does:**
1. Scans all directories in `LOOM_BLUEPRINT_PATHS`
2. Parses each YAML blueprint
3. Generates SQLAlchemy models
4. Writes to `backend/models.py`

**When to run:**
- After adding a new blueprint
- After modifying blueprint structure
- After adding/changing associations

**⚠️ Important:**
- Never edit `models.py` by hand
- It's always regenerated from blueprints
- Changes will be overwritten

---

### `loom generate migration`

Creates an Alembic database migration.

**Usage:**
```bash
loom generate migration -m "Add Company table"
loom generate migration -m "Add Contact associations"
loom generate migration --message "Update Deal fields"
```

**Required flag:**
- `-m, --message` — Description of the migration

**Output:**
```
⏳ Generating models from blueprints...
⏳ Running Alembic autogenerate...
  Generating /backend/migrations/versions/2026_04_27_add_company_table.py ...  done
✅ Migration generated. Don't forget to run 'alembic upgrade head'
```

**What it does:**
1. Runs `loom generate schema` first
2. Compares current models to database
3. Creates migration file with differences
4. Places in `migrations/versions/`

**Next steps:**
```bash
cd backend
alembic upgrade head              # Apply migration
python3 rbac_setup.py             # Sync new permissions
python3 rbac_drift.py             # Verify permissions
```

## Workflow: Adding a New Blueprint

Complete workflow from new blueprint to working API:

```bash
# 1. Create the blueprint
vim blueprints/product.yaml

# 2. Validate the blueprint
loom lint blueprints

# 3. Generate migration
loom generate migration -m "Add Product table"

# 4. Apply migration
cd backend
alembic upgrade head

# 5. Sync permissions
python3 rbac_setup.py

# 6. Restart server (for now, hot-reload coming)
# Ctrl+C to stop, then:
loom run dev
```

## Workflow: Adding Fields to Existing Blueprint

Adding fields (no migration needed):

```bash
# 1. Edit blueprint
vim blueprints/product.yaml
# Add new fields to the fields: list

# 2. Validate
loom lint blueprints

# 3. Regenerate models
loom generate schema

# 4. Restart server
# Ctrl+C, then:
loom run dev
```

**Why no migration?** Fields are stored in JSONB `data` column, so no database schema change needed.

## Workflow: Adding Associations

Associations create foreign keys (migration required):

```bash
# 1. Add association to blueprint
vim blueprints/product.yaml
# Add:
# associations:
#   - type: belongs_to
#     target: Category

# 2. Validate
loom lint blueprints

# 3. Generate migration (must include schema changes)
loom generate migration -m "Add Category to Product"

# 4. Apply migration
cd backend
alembic upgrade head

# 5. Restart
loom run dev
```

## Migration File Structure

Generated migration files look like:

```python
# migrations/versions/2026_04_27_add_company_table.py
"""Add Company table

Revision ID: abc123
Revises: xyz789
Create Date: 2026-04-27 10:00:00

"""
from alembic import op
import sqlalchemy as sa

# revision identifiers
revision = 'abc123'
down_revision = 'xyz789'
branch_labels = None
depends_on = None

def upgrade():
    # ### commands auto generated by Alembic - please adjust! ###
    op.create_table('companies',
        sa.Column('id', sa.Integer(), nullable=False),
        sa.Column('data', sa.JSON(), nullable=True),
        sa.PrimaryKeyConstraint('id')
    )
    # ### end Alembic commands ###

def downgrade():
    # ### commands auto generated by Alembic - please adjust! ###
    op.drop_table('companies')
    # ### end Alembic commands ###
```

**⚠️ Never edit the `upgrade()` or `downgrade()` functions by hand.**

## Error: Missing Migration Message

```
LOOM-E004: --message is required for 'loom generate migration'
```

**Fix:** Add `-m` flag:

```bash
loom generate migration -m "Add User table"
```

## Migration Best Practices

1. **Use descriptive messages:**
   ```bash
   # Good
   loom generate migration -m "Add Company and Contact tables"
   
   # Bad
   loom generate migration -m "update"
   ```

2. **One logical change per migration:**
   - Don't combine unrelated changes
   - Easier to rollback if needed

3. **Review before applying:**
   ```bash
   cat backend/migrations/versions/2026_04_27_*.py
   ```

4. **Test migrations:**
   ```bash
   alembic upgrade head      # Apply
   alembic downgrade -1      # Test rollback
   alembic upgrade head      # Re-apply
   ```

5. **Commit migrations:**
   ```bash
   git add backend/migrations/versions/
   git commit -m "Add migrations for Product feature"
   ```

## Rollback a Migration

If something goes wrong:

```bash
cd backend

# Rollback one migration
alembic downgrade -1

# Rollback to specific version
alembic downgrade abc123

# Rollback all the way
alembic downgrade base
```

## View Migration History

```bash
cd backend

# List all migrations
alembic history --verbose

# Show current migration
alembic current

# Show pending migrations
alembic history --verbose | grep -v "(head)"
```

## Common Issues

### "No changes detected"

```
INFO  [alembic.env] No changes in schema detected.
```

**Cause:** Models haven't changed since last migration.

**Fix:**
- Ensure you ran `loom generate schema` first
- Check that blueprints actually changed
- May need to edit blueprint to trigger change detection

### "Target database is not up to date"

```
alembic.util.exc.CommandError: Target database is not up to date.
```

**Fix:**
```bash
alembic upgrade head    # Apply pending migrations first
```

### Circular dependency

```
Circular dependency detected
```

**Cause:** Blueprints reference each other in a loop.

**Fix:** Redesign associations to break the cycle.
